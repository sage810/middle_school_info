# lesson-check — 활동지 점검

## 1. 자동 검사 (항상)

```
npm run check -- <차시>          # 여러 개: 05 06 · 전체: 인자 없이
```
✖ 가 있으면 원인을 찾아 `lesson-edit` 규칙대로 고치고 다시 돌린다. 캡처는 `dist/check/`.

## 2. 새 눈 검수 (요청받았을 때, 또는 큰 변경 뒤)

검수 기준은 가져온 외부 스킬 **better-interface**(접근성·레이아웃·문구·타이포·색·UI 6분야, `.claude/external-skills.md`)를 쓴다.
**방금 고친 것만** 보고 싶다고 하면 이 절 대신 선생님께 `/interface-review` 를 권한다(직접 불러야 하는 스킬).

만든 사람이 스스로 보면 놓치기 쉬워서, **범용 서브에이전트(Agent 도구, subagent_type 생략 = general-purpose)** 에게 맡긴다.
프롬프트는 `references/review-prompt.md` 를 읽어 `<차시>` 를 채워서 그대로 보낸다. 서브에이전트는 **고치지 않고 보고만** 한다.
여러 차시면 차시마다 서브에이전트를 **동시에** 띄운다.

돌아온 목록을 선생님께 요약해 보여 주고, 고칠 항목을 고르면 `lesson-edit` 로 고친다.
색 계열 선택·예시 문구 교체처럼 판단이 필요한 건 먼저 묻는다.

## 3. 학생 입장 동작 테스트 (요청받았을 때)

`npm run check` 가 못 보는 것 — 실제로 입력하고 누르는 흐름 — 은 정답지 스크립트로 흉내 낼 수 있다:
`answers.json` 을 채운 뒤 `npm run teacher -- <차시>` 가 PDF 까지 받아지면 입력 → 채점 → 진행률 → PDF 저장 흐름이 동작하는 것.
오답 피드백·다시 풀기 같은 세부 동작은 review-prompt 의 "학생 사용성" 항목으로 서브에이전트가 확인한다.
